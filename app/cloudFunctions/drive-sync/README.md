# Ghost annual Drive sync

1. In the `ghost-server-configuration` checkout, push the Apps Script code with clasp and publish an updated web app version using the Google account that can write to the annual Drive root. Set the script property `GHOST_DRIVE_SYNC_SECRET` to a randomly generated shared secret.
2. In this repository, set the Firebase secret of the same name with `firebase functions:secrets:set GHOST_DRIVE_SYNC_SECRET --project <project-id>`. Configure `GHOST_DRIVE_SYNC_URL` with the Apps Script web app's `/exec` URL when prompted during deploy.
3. Run `firebase deploy --only functions:ghost-drive-sync --project <project-id>`. The codebase contains the Firestore trigger and the callable scaffold function.
4. For each developer who should see the scaffold button, use the Firebase Admin SDK to add the custom claim `ghostDriveAdmin: true`, preserving their existing claims. They can sign in again to refresh the token.
5. Use the members sidebar to scaffold the active year and confirm the sheet opens. Verify with a completed PayPal contract and a later edit. Inspect Cloud Functions logs using the Firebase contract ID if Google writes fail.

The trigger reacts to writes after deployment. It uses the recorded completed capture receipt and does not query PayPal. On the first qualifying write for a receipt without an event year, the trigger records the active year on the receipt. Later edits use that year. Before enabling the trigger, confirm that untagged completed receipts that may still be edited belong to the active year. The current app stores payment markers in the contract itself, so the trigger does not independently establish the authenticity of that marker. Scaffolding creates the annual folder and master spreadsheet only. It does not backfill existing contracts. The script stops on ambiguous duplicate names within the selected parent.
